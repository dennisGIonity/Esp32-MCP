What it is

A self-contained copy of the Ionity ESP32-MCP fleet stack. ESP32 boards report telemetry over MQTT; the fleet server stores it, streams it live to the dashboard, and exposes the whole fleet to AI assistants through the Model Context Protocol (MCP). Everything shown on the dashboard comes from real devices — the only simulated device is the one you add yourself with DEMO-DEVICE.cmd.

Quick start

Needs Windows 10/11, Python 3.11+ (tick Add to PATH), and Chrome or Edge. No admin rights.

  1. Unzip the package anywhere, for example C:\Ionity\ESP32-MCP-Testers.
  2. Double-click SETUP.cmd once. It creates two private Python environments and a .env config (1–3 minutes).
  3. Double-click START.cmd. The broker and server start in the background and the dashboard opens at http://127.0.0.1:8099/. If Windows Firewall asks, allow Private networks.
  4. Flash a board with FLASH-BOARD.cmd (next section), or click DEMO-DEVICE.cmd if you have no hardware.
  5. When finished, STOP.cmd. Your data stays in data\fleet.db for next time.

The .cmd files

FileWhat it does
SETUP.cmdFinds Python, creates .venv and .venv-broker, installs pinned packages, writes .env. Safe to rerun.
START.cmdStarts the MQTT broker (:1883) and the fleet server (:8099), prints status, opens the dashboard.
STATUS.cmdBroker, server, MQTT link, MCP version and tool count, device counts, and the LAN address other PCs can use.
STOP.cmdStops only the processes this package started.
OPEN-DASHBOARD.cmdOpens the dashboard in your browser.
FLASH-BOARD.cmdOpens the web flasher with the bundled firmware images.
RUN-TESTS.cmdRuns the server test suite. Expect every test to pass.
DEMO-DEVICE.cmdAdds one simulated board, labelled DEMO – simulated, group emulated.
PURGE-DEMO.cmdStops and deletes the demo board from the database.

Flash a board

  1. Plug the ESP32 in with a data USB cable. ESP32-S3 boards with two ports: use either; the flasher has an image for each.
  2. Run FLASH-BOARD.cmd (Chrome/Edge). Step 1 – MCP host is pre-filled; click Check to confirm it answers.
  3. Step 2 – Board & firmware: Select USB port, then Identify chip. Keep From host firmware and tick Erase the whole flash first for a new board.
  4. Step 3 – WiFi & MCP: pick the 2.4 GHz network (Scan helps), enter its password, role Node. Optionally set Site, Group and Label – they show on the dashboard. Leave the MCP host empty to use mDNS.
  5. Step 4: click Flash & provision and watch the log. WiFi details go to the board over USB; the server never stores them.
  6. The board reboots, joins WiFi, finds the server (ionity-fleet.local) and appears on the dashboard within ~30 s.

ESP32 boards use 2.4 GHz WiFi only. The board and this PC must be on the same network, and Windows Firewall must allow ports 8099 and 1883 on a Private network.

Use with Claude Desktop (MCP)

Add this to %APPDATA%\Claude\claude_desktop_config.json, adjusting the folder, then restart Claude Desktop:

{ "mcpServers": { "ionity-esp32-fleet": {
    "command": "C:\\Ionity\\ESP32-MCP-Testers\\.venv\\Scripts\\python.exe",
    "args": ["C:\\Ionity\\ESP32-MCP-Testers\\server\\mcp_stdio_proxy.py"] } } }

Try: “Give me a fleet health check”, “Ping lab-node-01 and tell me the reply”. HTTP clients can call JSON-RPC directly at POST /api/v1/mcp/rpc.

Troubleshooting

SymptomFix
“Python 3.11+ was not found”Install Python with Add to PATH, close the window, run SETUP.cmd again.
Server shows downRead logs\server_err.txt. If the port is busy, change IONITY_PORT in .env.
Board never appearsSame 2.4 GHz network as the PC; firewall allows 8099 and 1883 (Private); check the flasher log for the server address found.
Commands return 401IONITY_ADMIN_TOKEN is set – enter it when the dashboard asks.
Flasher has no portsUse Chrome or Edge, a data cable, and install the CH340/CP210x driver if the board uses one.
Windows blocks a programSmart App Control: setup already avoids compiled packages; rerun SETUP.cmd and report the message.
