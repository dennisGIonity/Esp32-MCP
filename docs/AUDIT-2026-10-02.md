### Data flow (as implemented, verified against code)

```
ESP32 node ──MQTT qos0 ionity/<site>/<id>/telemetry──► MqttBridge (paho thread)
           ──MQTT qos1 .../status (retained + LWT)──►   │ call_soon_threadsafe
           ──HTTP POST /api/v1/telemetry (fallback)──►  ▼
                                               FleetRegistry.ingest()      (RAM, O(1))
                                                 ├─ devices{} hot view ──► WS /ws/fleet (2 s frames)
                                                 ├─ sinks → DatadogForwarder (15 s flush)
                                                 └─ asyncio.Queue(20k) ──► writer task
                                                                            ├─ SQLiteStore (batch, 1 commit/s)
                                                                            └─ alert engine → alerts table
Agent ──MCP JSON-RPC (HTTP /api/v1/mcp/rpc | stdio proxy)──► FleetMCPServer → tools.execute()
       device_call_tool ──MQTT .../cmd {"action":"mcp","rpc":…}──► DeviceMcp.ino → .../cmd/result ──► Future
LAN clients ──UDP :53──► DnsService (logging forwarder) ──► dns_queries / lan_devices
```

State lives in three places: the registry dict (authoritative for "now"), SQLite (history), and NVS on each board (identity, WiFi, tokens, mode). The on-board state machine (`ACTIVE/STANDBY/INFERENCE_ACTIVE/LOW_POWER_SLEEP/FAILSAFE`) is persisted in NVS except `LOW_POWER_SLEEP`, which is correctly treated as transient.

### What is already done well

The security model is thought through (admin token on every write path, per-tool read/write classification shared by REST, MCP and the firmware; secrets never committed; `hmac.compare_digest`; parameterised SQL everywhere; every dashboard string escaped). The ingest path is correctly O(1) with a single batched writer, the WAL is truncated on checkpoint, and the stdio bridge's "survive a dead backend" design is exactly right for Claude Desktop. The flasher is production-grade: SHA-256 verification of images, NVS-preserving partial writes, native-USB re-enumeration handling, redaction of secrets in the on-screen log, and strict TypeScript. Tests exist at every layer and pass. The findings below are therefore about the remaining defects and the hardening needed before this leaves the lab, not about a codebase that is broken.

## 3. Findings and drop-in solutions

### F-01 · Critical · network-sentinel does not import

**Location:** `modules/network-sentinel/core/security_analyzer.py:4` and `:115`

**Flaw.** `simulate_random_threat()` is annotated `-> Optional[Dict[str, Any]]` but `Optional` is not imported and the module has no `from __future__ import annotations`, so the annotation is evaluated at definition time. Importing `core.security_analyzer` raises `NameError`; `api/main.py` imports it, so `python run.py` dies at startup and all 13 sentinel tests error during collection. The CI `sentinel` job has been red since the merge commit `2fa9031`.

**Modern standard.** Import what you annotate, or use PEP 604 `dict[str, Any] | None` with `from __future__ import annotations` so annotations are never evaluated at import. Add an import-smoke test so a module that cannot import can never pass CI again.

**Fix (verified: 13/13 tests pass):**

```python
# modules/network-sentinel/core/security_analyzer.py  (line 4)
from typing import Any, Dict, List, Optional
```

```python
# modules/network-sentinel/tests/test_imports.py  (new)

@pytest.mark.parametrize("mod", [
```

### F-02 · Critical (before any deployment) · every `cmd` message is trusted

**Locations:** `infra/mosquitto/config/mosquitto.conf:23` (`allow_anonymous true`); `Esp32_MCP_Node.ino:435-442` ("MQTT is trusted … write tools are allowed"); `devices/pi-agent/ionity_agent.py:400-401` (`reboot` → `systemctl reboot`, unit runs as `root`); `ionity/broadcast/cmd` subscribed by every node.

**Flaw.** The host enforces `IONITY_ADMIN_TOKEN` on *its* write paths, but the boards and the Pi accept anything that arrives on their `cmd` topic. With the shipped broker config, any device that can reach TCP 1883 can publish `{"action":"mcp","rpc":{"method":"tools/call","params":{"name":"set_actuator","arguments":{"channel":"relay0","value":1}}}}` to `ionity/broadcast/cmd` and switch every relay in the fleet, put every board in `FAILSAFE`, or reboot every Pi. The firmware comment that MQTT is trusted is only true if the broker authenticates and authorises publishers — today it does neither. `ARCHITECTURE.md` lists this under "bench defaults — change before deployment", so the gap is known; what is missing is the production configuration, which the stack already fully supports (the flasher provisions `mqtt_user`/`mqtt_pass`, the server reads `IONITY_MQTT_USERNAME/PASSWORD`, the Pi agent reads `mqtt_username/mqtt_password`).

**Modern standard.** Authenticate every MQTT client and authorise by topic with an ACL. Boards share one low-privilege identity constrained by a `pattern` rule keyed on client id (`%c` = the board's `device_id`), so a board can only publish *its own* telemetry/status/result topics and read *its own* cmd topic plus `broadcast/cmd`. Only the fleet server identity may publish to `+/+/cmd` or `broadcast/cmd`. This removes the attack without any firmware change and keeps the "MQTT is trusted" assumption honest.

**Fix — `infra/mosquitto/config/mosquitto.conf` (replace the Auth block):**

```conf
# --- Auth -------------------------------------------------------------------
# Every client authenticates; topic access is governed by the ACL below.
#   docker compose exec mosquitto mosquitto_passwd -c /mosquitto/config/passwd ionity_server
#   docker compose exec mosquitto mosquitto_passwd    /mosquitto/config/passwd ionity_fleet
#   docker compose exec mosquitto mosquitto_passwd    /mosquitto/config/passwd ionity_tools   # MQTT Explorer etc.
allow_anonymous false
password_file /mosquitto/config/passwd
acl_file      /mosquitto/config/acl
```

### F-03 · High · offline-buffer replay destroys reading timestamps

**Locations:** `Esp32_MCP_Node.ino::buildTelemetryJson` (lines 244-286, 624-631); `server/app/models.py::TelemetryIn.at`

**Flaw.** `Sample` carries `ts_ms`, but `buildTelemetryJson()` never emits it, and `uptime_s`/`seq` are taken from *now*, not from the sample. When `flushBuffer()` replays up to 40 samples, the server stamps each one `time.time()` on arrival, so seven minutes of history collapse into one second. The live database proves it: 17 occurrences of five or more rows for the same board inside one second. Any trend query, `aggregate_metric` or Datadog graph over a reconnect window is wrong. Separately, when a device *does* send `ts`, the server trusts it unconditionally — a board with an unset RTC (1970) or a wrong clock would write history anywhere in the table.

**Modern standard.** Devices without an RTC should report *relative* age (`age_ms = now - sample.ts_ms`); the server backdates against its own clock and clamps any absolute device timestamp to a sane skew window. This is the pattern used by every mature IoT ingest (AWS IoT `timestamp` offsets, Azure IoT `iothub-enqueuedtime` vs device time).

**Fix — firmware (`Esp32_MCP_Node.ino`), two lines in `buildTelemetryJson` and a version bump in `config.h`:**

```cpp
// config.h
#define FW_VERSION            "2.0.1"   // 2.0.1: age_ms on every reading so buffered samples keep their time; hardened dns_probe parser
```

```cpp
// Esp32_MCP_Node.ino :: buildTelemetryJson(const Sample &s), after doc["seq"]:
  // How old this reading is. Live samples: a few ms. Replayed buffer entries:
  // up to ~7 min. The host subtracts it so history keeps its real shape.
  // Unsigned subtraction is wrap-safe across the 49-day millis() rollover.
  doc["age_ms"]    = (uint32_t)(millis() - s.ts_ms);
```

**Fix — server (`server/app/models.py`, in the patch, tests pass):**

```python
class TelemetryIn(BaseModel):
    device_id: str = Field(min_length=3, max_length=64)
    site: str = "ionity-local"
    group: str = "default"
    label: str | None = None
    fw: str | None = None
    product: str | None = None
    uptime_s: int | None = None
    seq: int | None = None
    metrics: dict[str, float | int | bool | str] = Field(default_factory=dict)
    net: NetInfo = Field(default_factory=NetInfo)
    ts: float | None = None          # server fills if device has no RTC
    # fw >= 2.0.1: how old this reading is relative to the moment the board
    # sent it. A board with no RTC that replays its offline buffer sets this,
    # so 40 buffered samples land at their real times instead of one burst.
    age_ms: int | None = Field(default=None, ge=0, le=7 * 86400 * 1000)
    mode: str | None = None          # fw >= 2.0 state mode

    # A device clock may be unset (1970) or wrong; never let it write history
    # more than this far from the server's clock.
    MAX_SKEW_S: ClassVar[float] = 600.0

    def at(self, received_at: float | None = None) -> float:
        now = received_at if received_at is not None else time.time()
        if self.ts and abs(self.ts - now) <= self.MAX_SKEW_S:
            base = self.ts
        else:
            base = now
        if self.age_ms:
            base -= self.age_ms / 1000.0
        return base
```

`FleetRegistry.ingest()` now computes `eff = t.at(now)` once, queues `(t, eff)`, and the writer/alert engine use `eff` (see F-12 for the writer). The Pi agent and emulator need no change (`age_ms` is optional); the Pico sketch emits live readings only.

### F-04 · High · `dnsProbe` reply parser bounds, and 18 s inside the MQTT callback

**Location:** `Esp32_MCP_Node.ino:317-377`, called from `onMqttMessage` (line 456-488)

**Flaw.** In the answer loop the bounds check `p + 10 < got` is evaluated *before* the name is skipped; after skipping a label sequence `p` can exceed `got` and `r[p]..r[p+9]` are read past the valid data (within the 512-byte stack buffer, so it is an information-quality bug, not a crash — but a hostile resolver can also make the label walk `p += r[p] + 1` leave the buffer when `got == 512`). Additionally, `dns_probe` with 12 names × 1.5 s timeout blocks `loop()` for up to 18 s: no `mqtt.loop()`, no `/mcp` HTTP, no serial provisioning, no OLED, and the keepalive margin (60 s) shrinks.

**Modern standard.** Parse with a cursor that is checked before *every* read; run multi-second work as a state machine across `loop()` iterations (or a FreeRTOS task) so the node stays responsive.

**Fix — hardened parser (drop-in replacement for `dnsProbe`):**

```cpp
// ---------------------------------------------------------------------------
// DNS probe: one raw A query over UDP to ONE resolver. Every read of the reply
// is bounds-checked against `got` (a hostile or truncated reply must never
// make the parser read outside the bytes we actually received).
// ---------------------------------------------------------------------------
#include <WiFiUdp.h>

static bool dnsSkipName(const uint8_t *r, int got, int &p) {
  int hops = 0;
  while (p < got) {
    uint8_t len = r[p];
    if (len == 0) { p += 1; return true; }
    if ((len & 0xC0) == 0xC0) { p += 2; return p <= got; }   // compression pointer ends the name
    if (len > 63 || ++hops > 128) return false;
    p += 1 + len;
  }
  return false;
}

String dnsProbe(const IPAddress &server, const String &name, uint32_t &elapsedMs) {
  uint8_t q[300];
  uint16_t id = (uint16_t)esp_random();
  size_t len = 0;
  q[len++] = id >> 8; q[len++] = id & 0xff;
  q[len++] = 0x01; q[len++] = 0x00;            // RD
  q[len++] = 0; q[len++] = 1;                  // QDCOUNT 1
  for (int i = 0; i < 6; i++) q[len++] = 0;    // AN/NS/AR = 0
  int start = 0;
  while (start <= (int)name.length()) {
    int dot = name.indexOf('.', start);
    if (dot < 0) dot = name.length();
    int lab = dot - start;
    if (lab <= 0 || lab > 63 || len + lab + 6 > sizeof(q)) return "BADNAME";
    q[len++] = lab;
    for (int i = start; i < dot; i++) q[len++] = name[i];
    start = dot + 1;
  }
  q[len++] = 0;
  q[len++] = 0; q[len++] = 1;                  // QTYPE A
  q[len++] = 0; q[len++] = 1;                  // QCLASS IN

  WiFiUDP udp;
  if (!udp.begin(0)) { elapsedMs = 0; return "NOSOCKET"; }
  uint32_t t0 = millis();
  udp.beginPacket(server, 53); udp.write(q, len); udp.endPacket();
  uint8_t r[512];
  int got = 0;
  while (millis() - t0 < DNS_PROBE_TIMEOUT_MS) {
    if (udp.parsePacket() > 0) {
      got = udp.read(r, sizeof(r));
      if (got >= 12 && r[0] == q[0] && r[1] == q[1] && (r[2] & 0x80)) break;  // our id, a response
      got = 0;
    }
    delay(2);
  }
  elapsedMs = millis() - t0;
  udp.stop();
  if (got < 12) return "TIMEOUT";

  uint8_t rcode = r[3] & 0x0f;
  if (rcode == 3) return "NXDOMAIN";
  if (rcode == 2) return "SERVFAIL";
  if (rcode == 5) return "REFUSED";
  if (rcode != 0) return "RCODE" + String(rcode);

  uint16_t qd = (r[4] << 8) | r[5];
  uint16_t an = (r[6] << 8) | r[7];
  int p = 12;
  for (uint16_t i = 0; i < qd; i++) {               // skip the question section
    if (!dnsSkipName(r, got, p)) return "BADREPLY";
    p += 4;                                           // QTYPE + QCLASS
    if (p > got) return "BADREPLY";
  }
  for (uint16_t i = 0; i < an; i++) {
    if (!dnsSkipName(r, got, p)) return "BADREPLY";
    if (p + 10 > got) return "BADREPLY";              // TYPE CLASS TTL RDLEN
    uint16_t type  = (r[p] << 8) | r[p + 1];
    uint16_t rdlen = (r[p + 8] << 8) | r[p + 9];
    p += 10;
    if (p + rdlen > got) return "BADREPLY";
    if (type == 1 && rdlen == 4)
```

### F-05 · High · LAN DNS resolver is an open resolver with unbounded fan-out

**Location:** `server/app/ingest/dns_resolver.py` (`_ServerProtocol.datagram_received`, `DnsService.handle`, `_forward`); `config.py` (`dns_bind = "0.0.0.0"`)

**Flaw.** Four related issues. (1) Any source IP is answered — on a host with a public or guest-network interface this is a textbook amplification reflector (a 60-byte query yields a 500-byte reply to a spoofed victim). (2) `asyncio.create_task()` return values are discarded; the asyncio docs warn such tasks can be garbage-collected mid-flight, and there is no cap, so a flood creates unbounded tasks, each opening a new UDP socket per upstream. (3) The cache is only swept when it exceeds 5,000 entries and only drops *expired* ones; a scan of random names with long TTLs grows it without limit. (4) `_forward` accepts any datagram from the upstream socket as the answer without checking the transaction id or the QR bit. The `fut` closure flagged by ruff (B023) is harmless today but fragile.

**Modern standard.** Allow-list client networks (drop silently, never REFUSE — a REFUSED reply is still reflection), hold task references in a bounded set, cap and evict the cache, validate upstream replies by id, and make all of it observable in `stats()`.

**Fix (in the patch; unit-tested):** new setting in `config.py`


### F-11 · Medium · Pi agent: ineffective `will_set`, blocking command handlers

**Location:** `devices/pi-agent/ionity_agent.py:435-446, 464-483`

**Flaw.** `apply_meta()` calls `self.mqtt.will_set(...)` on a connected client; paho only sends the Will during CONNECT, so after a `set_meta` the broker still holds the *old* topic's Will until the next reconnect. `_on_message` runs `handle_command()` on paho's network thread; `dns_probe` can block it for 18 s, during which no PINGREQ/PUBLISH is processed and the queued telemetry stalls.

**Fix:**

```python
    def apply_meta(self, changed: dict) -> None:
        old_cmd = self.topic("cmd")
        if self.mqtt and self.mqtt_ok:
            self.mqtt.publish(self.topic("status"), json.dumps(self.status("offline")), qos=1, retain=True)
        self.site = changed.get("site", self.site)
        self.group = changed.get("group", self.group)
        self.label = changed.get("label", self.label)
        if self.mqtt and self.mqtt_ok:
            self.mqtt.unsubscribe(old_cmd)
            self.mqtt.subscribe(self.topic("cmd"), 1)
            self.mqtt.publish(self.topic("status"), json.dumps(self.status("online")), qos=1, retain=True)
            # A Will is only registered at CONNECT. Re-arm it on the new topic by
            # bouncing the session; paho's loop thread reconnects on its own.
            self.mqtt.will_set(self.topic("status"), json.dumps(self.status("offline")), qos=1, retain=True)
            self.mqtt.disconnect()
            self.mqtt.reconnect()

    def _on_message(self, client, userdata, msg):
        try:
            doc = json.loads(msg.payload.decode("utf-8", "replace") or "{}")
        except ValueError:
            return
        if not isinstance(doc, dict):
            return
        log.info("cmd <- %s", doc.get("action"))
        # Never block paho's network thread: a dns_probe can take 18 s.
        threading.Thread(target=self._run_command, args=(client, doc), daemon=True,
                         name=f"cmd-{doc.get('cmd_id', '')}").start()

    def _run_command(self, client, doc: dict) -> None:
        try:
            ok, detail, after = self.handle_command(doc)
        except Exception as e:                     # noqa: BLE001
            ok, detail, after = False, f"agent error: {e}", None
        reply = {"device_id": self.device_id, "cmd_id": doc.get("cmd_id", ""), "ok": ok, "detail": detail}
        info = client.publish(self.topic("cmd/result"), json.dumps(reply), qos=1)
        if after:
            try:
                info.wait_for_publish(2)
            except Exception:                      # noqa: BLE001
                log.debug("result publish not confirmed before running after-action", exc_info=True)
            after()
```

### F-14 · Medium · on-device HTTP MCP: unbounded body, unauthenticated `/info`, token compare

**Location:** `DeviceMcp.ino:275-299, 311-316`

**Flaw.** `WebServer` buffers the whole POST body into a `String`; a 200 KB POST to `/mcp` exhausts heap on a 4 MB-flash/320 KB-RAM board (a trivial LAN DoS). `GET /info` returns site, label, host, IP and tool list without the token even when one is provisioned. `h == "Bearer " + token` is a short-circuiting compare.

**Fix:**

```cpp
#define MCP_HTTP_MAX_BODY  6144     // tools/call payloads are < 1 KB; input_frame of 64 floats < 2 KB

static bool tokenEquals(const String &a, const String &b) {   // constant-time for equal lengths
  if (a.length() != b.length()) return false;
  uint8_t diff = 0;
  for (size_t i = 0; i < a.length(); i++) diff |= (uint8_t)a[i] ^ (uint8_t)b[i];
  return diff == 0;
}

static int httpAuth() {             // 0 = none, 1 = read, 2 = read+write
  if (gCfg.mcpToken.length() == 0) return 1;
  String h = mcpHttp.header("Authorization");
  return (h.startsWith("Bearer ") && tokenEquals(h.substring(7), gCfg.mcpToken)) ? 2 : 0;
}

static void handleMcpPost() {
  corsHeaders();
  int auth = httpAuth();
  if (auth == 0) { mcpHttp.send(401, "application/json", "{\"error\":\"bearer token required\"}"); return; }
  const String &body = mcpHttp.arg("plain");
  if (body.length() > MCP_HTTP_MAX_BODY) {
    mcpHttp.send(413, "application/json", "{\"jsonrpc\":\"2.0\",\"id\":null,\"error\":{\"code\":-32600,\"message\":\"request too large\"}}");
    return;
  }
  JsonDocument req;
  if (deserializeJson(req, body)) {
    mcpHttp.send(400, "application/json", "{\"jsonrpc\":\"2.0\",\"id\":null,\"error\":{\"code\":-32700,\"message\":\"Parse error\"}}");
    return;
  }
  if (req.is<JsonArray>()) {
    mcpHttp.send(400, "application/json", "{\"jsonrpc\":\"2.0\",\"id\":null,\"error\":{\"code\":-32600,\"message\":\"batches not supported\"}}");
    return;
  }
  JsonDocument resp;
  mcpDispatch(req.as<JsonObjectConst>(), resp, auth == 2);
  if (resp.isNull() || resp.size() == 0) { mcpHttp.send(202); return; }
  String out; serializeJson(resp, out);
  mcpHttp.send(200, "application/json", out);
}

// /info: same rule as the MCP endpoint - open when no token is provisioned,
// otherwise it needs the token too (it reveals site/label/host/IP).
  mcpHttp.on("/info", HTTP_GET, []() {
    corsHeaders();
    if (httpAuth() == 0) { mcpHttp.send(401, "application/json", "{\"error\":\"bearer token required\"}"); return; }
    JsonDocument d; fillInfo(d);
    String out; serializeJson(d, out);
    mcpHttp.send(200, "application/json", out);
  });
```

Note `WebServer` still reads the body before the handler runs; `MCP_HTTP_MAX_BODY` bounds what is *parsed*, and `mcpHttp.setContentLength` cannot pre-reject. For a hard cap, call `mcpHttp.client().setTimeout(2)` in `mcpHttpBegin()` so a slow-loris body is dropped after 2 s, which is sufficient on a LAN-only interface.
